# 版本说明

## 0.5.4 · 2026-11-14

- Codex 和 DSH 的会话检查显示当前可用的会话状态。采集暂忙时继续显示同一会话最近可用的摘要，读取失败或无可用摘要时显示原因。
- JEV 每轮最多取 100 条相关原始记录，和合并摘要一起用于判断阻塞。
- Codex 和 DSH 每个会话最多保留 200 条采集记录。DSH 在提交采集批次前合并同一输出的流式片段。

## 0.5.3 · 2026-11-13

- Codex 侧栏在观察服务交接时可以先读取本地页面。恢复的隐藏侧栏会先完成握手，显示后再读取会话。
- 每项总结请求最多输出 256 token，关闭思考，正文提示为一到两句。三项请求仍共用证据前缀，合并后交给 JEV 判断。
- Codex 和 DSH 的会话检查直接显示总结模型超时及重试状态。

## 0.5.2 · 2026-11-13

- Codex 和 DSH 的会话检查在观察服务超时时显示连接状态，并在原侧栏自动恢复。上次成功读取的摘要和 JEV 判断会标为旧结果。
- 修复并发启动时旧进程的清理误删新锁的问题。Codex 可重新确认仍在线的观察进程并补回丢失的锁。

## 0.5.0 · 2026-11-12

- DSH 和 Codex 在同一份会话检查页面显示当前问题、详情和总览。DSH 的右侧栏和 GS 弹层使用相同页面。总览按页读取各自 Core 的会话数据。
- DSH 插件升级时先核对 Core 版本，等待旧进程释放后自动连接新版。此前保留的会话资料和安装设置仍可读取。
- DSH 的预期后台清单可在 Sentinel 设置的「连接诊断」中管理。

## 0.4.9 · 2026-11-12

- 修复 DSH 的 Sentinel 侧栏读取当前会话时可能超时的问题。Core 直接返回该会话的状态、摘要、JEV 判断和历史。
- 升级 DSH 插件后需加载新版 Core，才能使用按会话读取的接口。

## 0.4.8 · 2026-11-12

- 预填取消后等待 5 秒。旧操作仍未释放且有空闲并发名额时，为同一会话用独立缓存补跑一次总结。
- Codex 和 DSH 侧栏同时显示旧预填待释放与新总结的状态。补跑使用新版 Sentinel Core。

## 0.4.7 · 2026-11-12

- Codex 会话检查固定使用 0.4.6 已登记的面板地址。插件升级时，原标签页仍可匹配同一入口，页面内容按插件版本更新。
- 正式版和测试版各自保留原有地址。更早的资源地址仍可读取当前页面。

## 0.4.6 · 2026-11-11

- Codex 和 DSH 共用新版会话检查页面。顶部左侧并排显示当前会话灯和 JEV 状态，更新时间靠右。
- JEV 的简短原因单独一行，原始依据可展开。

## 0.4.5 · 2026-11-11

- JEV 理由栏显示简短说明。工具路径、命令输出和目录列表留在“查看判断依据”中。
- Codex 和 DSH 的新判断及历史判断都使用同一规则。已明确的判断仍引用原始依据，待确认状态继续显示实际原因。

## 0.4.4 · 2026-11-11

- 普通模型继续用同一证据前缀分三次回答。Sentinel 按请求顺序添加标题。各项正文可以换行，取消单行和字数校验。
- Codex 和 DSH 面板保留各项正文的换行。合并摘要与原始依据交给 JEV 判断。
- Codex 检查 Core 是否支持多行摘要。旧 Core 退出后，观察器自动连接新版。

## 0.4.3 · 2026-11-11

- DSH 当前会话侧栏与 Codex 共用同一份检查面板。摘要正文为 15px，三项分行显示。DSH 的“全部会话”入口可打开全局总览。
- 总结模型依次发送三次请求，使用相同的证据前缀。合并摘要先显示，JEV 随后判断。JEV 超时或失败时保留本轮摘要并显示待确认。
- 普通摘要最多取 200 条证据。JEV 最多取 500 条相关原始记录，并有独立的输入预算。Codex 每个聊天的原生留存上限同步提高到 500 条。
- Codex 旧标签页可用原资源地址读取新版检查面板，新标签页使用由内容生成的地址。

## 0.4.2 · 2026-11-11

- 会话检查页面按 HTML 内容生成地址。页面有变化时，宿主可通过新地址加载新版，避免升级后沿用缓存中的旧页面。
- 新面板将“在做什么”“有什么进展”“卡在哪里”分三行显示。JEV 状态、原因和可展开的依据紧随摘要。

升级后从当前聊天重新打开“GhostSentinel 会话检查”。本地回归覆盖宿主先缓存旧页面、再取得新版页面的场景。实际升级表现由用户核对。

## 0.4.1 · 2026-11-11

- 每轮依次发送三次 LLM 请求，分别回答“在做什么”“有什么进展”“卡在哪里”。三次使用同一证据前缀。支持 GMD 预填时，共用同一缓存身份。
- 三个回答和引用通过校验后合并为三行。JEV 根据合并摘要和原始依据判断一次，状态、原因和引用显示在摘要旁。
- 任一回答无效时结束本轮，保留上次有效摘要。采集证据不足时，阻塞状态显示“待确认”。

本地用受控模型服务核对请求次序、前缀、缓存身份和 JEV 输入。实际缓存命中和升级后的模型效果由用户试用验证。

## 0.4.0 · 2026-11-11

- DSH 收到同一代理从运行进入空闲或结束的原生事件后，为有当前请求证据的执行补一次收尾摘要。摘要进入原有模型队列，结束后无需等待本轮冷却。
- DSH 的“详情”展示部分观察摘要和观察范围，并保留上次完整摘要。收尾只覆盖部分材料时显示“部分收尾摘要”，附原完成时间和证据引用。
- 收尾摘要按原有留存期限显示，历史摘要仍可展开。任务结束后的摘要不会触发新的任务告警。
- 总结模型在一次请求内读取同一份证据前缀，分别回答“在做什么”“有什么进展”“卡在哪里”。Codex 将三个回答分行显示，并在“上次总结”下直接显示 JEV 阻塞判断、原因和可展开的依据。判断缺失时显示待确认。

DSH 需要同时加载新版 Core。验证范围见本版发布报告。

## 0.3.9 · 2026-11-11

- JEV 在摘要完成后，通过同一次判断请求给出“已阻塞”“未阻塞”或“待确认”。摘要旁显示具体原因和可展开的原始依据。新材料到达或暂停分析后，旧结论标为“上次判断”。
- 执行摘要固定回答“在做什么”“有什么进展”“卡在哪里”。Codex 为已监控的执行补一次收尾摘要。
- Codex 的会话查询与模型分析分队列运行。默认查询并发 2 路、间隔 1.5 秒，模型分析默认 1 路。设置按安装保存，重复排队的执行合并最新材料。DSH 提供独立的模型分析并发设置。

本地检查通过受控模型响应验证判断流程、引用和面板展示。实际更新及用户现用 JEV 的判断效果由用户升级后复核。

## 0.3.8 · 2026-11-11

- 推进不足判断明确比较多轮活动及实际结果。引用核查、排除占用、确定保留范围和清理预检取得新事实均算推进，不因任务尚未完成或摘取模型没有选择推进分类而认定停滞。
- 本轮材料不足、超预算或尚未完成复核时，保留告警显示“待复核”、原判断时间及本轮复核说明，顶部提示也区分历史告警与当前判断。
- 推进告警优先展示原判断引用范围内的工具结果，后续结果不会冒充旧告警依据。相关新结果及独立恢复判断确认后才撤下告警。
- 观察器核对 `stalled-progress-review/1`，避免升级后继续使用旧 Core 的判断规则；旧私有实例自然退出后自动接续，独立 DSH Core 保持运行。

本地验证覆盖正常调查材料、JEV 请求、Core、MCP、面板、旧告警复核及恢复、旧 Core 接续和资源回收。实际插件升级及用户现用 GMD 的判断质量由用户升级后复核；完整验证与产物对应关系见本版报告。

## 0.3.7 · 2026-11-10

- Codex 按会话执行状态持续监控。中途接入正在运行的会话时，根据已有执行记录分析，无需用户再发送消息，也不要求先核实当前请求。
- 当前请求未核实时，继续生成附依据的活动总结，并按执行证据检查同类返工和完整验证重复成本。推进不足、偏离请求和当前版本本地验证缺口分别显示请求证据不足。
- 会话面板独立显示近期活动。尚未取得执行材料时继续采集，取得材料后再调度分析，避免空会话占用分析名额。
- 观察器核对 `chatgpt-execution-monitoring/1`。旧私有 Core 缺少该能力时，等待其自然退出并自动接入新版；独立 DSH Core 继续运行。

本地验证覆盖无用户消息的执行、真实分析 HTTP、Core、MCP、面板、预填缓存隔离、暂停恢复及旧 Core 接续。实际插件升级和用户现用 GMD 的表现由用户升级后复核；完整门禁与产物对应关系见本版验证报告。

## 0.3.6 · 2026-11-10

- 正常的记录淘汰、输出摘录和预算选材只说明观察范围，不再统一阻断六项检查。有充分证据的检查继续请求 JEV，缺当前请求、操作、验证或来源证据的项目单独显示原因。
- 总结与 JEV 共用预算内材料，保留当前请求和授权继承限制。模型输入仍为 24,000 字符，生成上限仍为 4,096 token。
- 绿色显示“已检查项未见异常”，同时说明仍缺证据的项目；有依据的异常继续为红色，未知判断不充当正常。顶部改为“已总结”，范围说明合并重复提示。
- 适配 additional_tools 工具目录声明：验证 role 和 tools 数组后跳过声明正文，不作为执行证据或用户授权；损坏结构和其他未知类型继续保持缺口。旧版该类型诊断不再阻断新分析。
- Core 核对逐项证据策略并使旧聚合结果重新判断；带范围限制的总结只有在 JEV 实际成功后才结算对应分析故障恢复。

归档排除、活动发现、每会话 100 条留存、防重放、模型配置和通知偏好保持。真实插件更新与当前 GMD 模型表现待用户复核，验证范围见本版报告。

## 0.3.5 · 2026-11-10

- Codex 归档聊天退出独立监控；空闲聊天只保留轻量活动发现，有新活动后自动恢复采集，不依赖侧栏打开。已接入的聊天先采集本轮结束记录，再关闭读取器。
- 只读接口的 notLoaded 和持久化 interrupted 不直接代表当前执行已停止。最近更新及后续变化只用于唤醒核验，实际开始和结束仍由本机记录证明。
- 同一安装内，每个聊天跨执行和重启合计最多保留 100 条原生采集记录。超额淘汰旧缓存，当前请求和开始证据优先保留；保留精确防重放标记，升级时自动收缩已有缓存。活跃分叉需要的归档祖先证据仍按需核验。
- 修复同一聊天切换原生存储记录后沿用旧游标而反复 cursor-invalid 的问题。各存储记录独立恢复，返回旧记录时保留原有采集时间和防重放进度。
- 目录和观察缓存占满时允许新活动聊天替换空闲缓存。正式采集核对 Core 的每会话留存能力，避免更新后静默沿用旧策略。

模型输入、生成预算和配置保持。淘汰造成的观察缺口继续明确列出，允许有引用的部分总结，不能据此显示完整正常。两端门禁及待验范围见本版验证报告。

## 0.3.4 · 2026-11-09

- 采集达到 10,000 条上限时，按首次采集时间淘汰最旧的已保存记录，为已确认的活跃会话腾出空间。正在运行的请求和开始证据优先保留。淘汰清理旧正文和证据定位，保留防重放标记。历史补读在容量释放后继续。

## 0.3.3 · 2026-11-09

- Codex 观察器核对 Core 的中文总结提示词能力，待旧私有实例退出后自动接入新版。已保存的总结按原生成内容展示。

## 0.2.10 · 2026-11-09

- 修复受管 GMD 总结请求继承默认思考预算、反复耗尽 4096 token 输出额度而返回 invalid_response 的问题。只为已声明受管能力的总结模型设置 thinking_token_budget 为 0，普通提供方、JEV 和 GMD 全局配置保持。
- 零输出预填与正式生成使用同一思考策略，缓存命名空间绑定该策略；实际发送的参数和缓存字段全部纳入原有 24000 字符输入预算。生成上限、短总结长度、引用核验、留存及精确防重放保持。
- Codex 根据 bounded-summary-generation/1 核对 Core 能力，避免更新观察器后继续使用旧分析代码。旧私有 Core 自然退出后重连新版，独立 DSH Core 继续运行。

使用同一份真实失败聊天材料进行对照：原请求约 20.7 秒耗尽 4096 token，以 length 结束并被 GMD 拒绝；只改思考预算后约 2.2 秒、283 token 正常结束并生成带引用的部分总结。最终生产代码另在真实材料上约 4.4 秒、256 token 完成。材料缺口继续列出，六项检查保持未知，不把部分总结记为完整判断成功。完整门禁、产物和未验范围见本版验证报告；发布不改写现用安装或模型配置。

## 0.2.9 · 2026-11-09

- 安装诊断将旧执行、执行未确认及已断开来源的未恢复采集故障单列，显示数量、最近一项原因及首次／最近发生时间；不再直接冒充本轮采集失败，也不删除或结算这些回执。

留存、容量、防重放、读取预算、补读调度、通知和模型配置保持。诊断读取不推进材料采集或调用模型；刷新、失败和页面切换清除旧展示。真实 GMD 新输出预算效果及实际更新后的界面仍待用户实测，验证范围见本版报告。

## 0.2.8 · 2026-11-08

- 长会话超出 24000 字符模型输入预算时，保留当前请求和全部授权继承限制，再选取最近记录生成部分总结；标记预算省略和数量，不清理原始留存，不改首次采集时间或防重放。必需材料仍超限时明确拒绝。
