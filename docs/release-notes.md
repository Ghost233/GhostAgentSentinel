# 版本说明

## 0.1.9 · 2026-10-28

从 0.1.8 递增为 0.1.9，DSH、Codex 正式版与 test 使用相同版本。按用户要求接通三方预填入口后发布，由用户下载测试；当前不操作 App、共享 Core 或模型服务。

- Core 按任务和来源索引事件，复用未变化的材料，避免维护时逐任务重扫全部历史；过期、补采和来源清理仍更新索引。
- 生产分析器接入 GMD 能力发现、零预算预填、正预算生成及 JEV；完整分析优先、前轮释放后接续，固定本轮材料，完成后冷却 60 秒，不增加冷回退。
- 缓存按安装、任务与角色隔离；取消、失联、未提交证明、结果丢失和晚到查询保留真实状态。结果未知不冒充成功，也不重复执行。
- Codex 的 MCP 壳层独立于观察资料和 Core 就绪；数据暂缺时保留面板与具体故障。模型目录补充 GMD 的文本／JEV 双角色分类。

本地 macOS arm64 最终完整检查与资源用例合并运行：1,908 项通过，0 失败，14 项原版能力不支持而跳过。语法、原版 DSH 包加载和两端分发校验通过。真实缓存、Tiel＋DFlash2、实际受管运行和运行 Core 的 CPU／响应尚未补验，不因发布记为通过；App 退出／重开仍留最后。预填需要配套 GMD 0.3.1 及声明支持的 GhostSplash／模型组合，旧 Core 不会因升级文件自动更新。

## 0.1.8 · 2026-10-23

从 0.1.7 递增到 0.1.8。Codex 正式版、test 和 DSH 安装版本一致，旧 tag 保留。

- 修复同路径、同 inode 的设备号变化被判为 `record-file-replaced`。只有保留的存储键、头部和可信前缀核验通过，才恢复物理绑定；inode 变化、截断、同大小改写及前缀变化继续拒绝。
- 将未锚定执行的同类恢复故障合并范围扩展至 `record-*` 和 `native_origin_*`，保留各聊天回执、原游标合并尝试及通知事实的区别。
- 启用原生通知的适配器在采集前检查 `monitoring-recovery-rollup/1`；旧 Core 缺少该能力时明确显示 `core-update-required`，不自动停止、替换或重启共享 Core。

本地完整 ChatGPT 回归 1,304 项及共享通知／服务回归 67 项通过。42 份现有主聊天记录已完成前缀核验，用户报告的约 2.66 MB 记录离线追平且未重发旧事件；45 条故障保留全部回执，只消费一次合成通知。仍有一份记录存在独立的未支持条目格式，部分执行身份尚未确认，均保留缺口，不计为完整正常。

当前 App 和运行中的 Core 不操作，由用户自行升级测试。实机升级、完整双端隔离及 App 退出重开仍未验，见 [发布验证范围](release-status.md)。

## 0.1.7 · 2026-10-22

从 0.1.6 递增到 0.1.7。Codex 正式版、test 和 DSH 安装版本一致，保留既有 tag。

- 修复旧 v2 读取进度因 App 运行代次变化而直接报 `cursor-invalid`。核对同安装原生账本、文件身份、头部及已确认前缀后继续读取，保留首采时间及分叉交付水位；重验中保持不可判断。
- 同安装、同宿主代次、同原因的未锚定游标故障合并一次通知。各聊天回执保留，其他原因和已确认执行的故障仍独立提醒。该行为需要运行新版共享核心，不自动替换现有 Core。

本地 1,286 项 ChatGPT 回归及 67 项共享通知回归通过。现有记录离线回放中，240 份旧游标可进入有界重验；241 条故障保留全部回执，其中 240 条同类游标故障只消费一次通知，另一种故障独立保留。回放未向系统发送通知，也不表示这些实际聊天的完整历史已经补齐。

版本、分发包及发布资产重新核对。当前 App、已安装插件和共享 Core 不操作，由用户自行升级测试。真实 App 升级、双端完整隔离与退出重开仍未验，见 [发布验证范围](release-status.md)。

## 0.1.5 · 2026-10-21

按用户要求从 0.1.4 累加补丁版本。DSH、Codex 正式版和 test 统一为 0.1.5，旧 tag 保留。正式版与 test 独立安装，各自保存配置、通知偏好和暂停状态。

- 同一 Codex 插件提供会话检查与全局安装设置，无需另一份设置插件。监控分为“当前问题”和“详情”，顶部 GS 在滚动时固定；DSH 设置使用原版宿主系统设置入口。
- 设置分为“设置”“通知记录”和“连接诊断”。两个模型按组自动保存，各有独立的“读取列表”和“检查连接”；半填草稿、保存失败和结果未知如实保留。

- 修复归档记录元路径仍为 `.jsonl`、但只剩同名 `.jsonl.zst` 时的 ENOENT。仅原文件确实不存在时回退，权限、越界和真正缺失继续报错；来源、历史和首采身份保持。
- 旧 Core 缺少通知能力时，请求前明确拒绝并提示更新。更新插件文件不会给旧进程补接口，也不自动替换或终止共享核心。

## 0.1.3 · 2026-10-19

本轮从仓库 0.1.2 累加补丁版本，将 DSH、Codex 正式版和 test 统一为 0.1.3。此前正式基线为 0.1.1，0.1.2 源码候选未创建正式 Release；旧 `0.1.2-preview.2` 为开发预览。

- 修复共享核心恢复大历史序号时触发的 `RangeError`，保留原有身份、去重、只读范围和留存要求。Codex 继续只观察本机主聊天及分叉主会话。
- 每份安装独立保存总结模型和 JEV 判断模型，同一安装内各聊天共用。DSH、Codex 正式版与名称以小写 `test` 结尾的测试版共用核心，分别管理配置及暂停。
- Codex 会话面板顶部固定提供“设置”，采集失败时仍可操作。两个模型分别设置服务地址与 ID，支持目录选择和手填；连接检查只读取 `GET /v1/models`，不发送聊天材料或推理。
- 总结模型整理证据并生成附依据的 1～2 句执行短总结。仅本轮总结模型和 JEV 均成功，且输出与引用有效时发布新总结；失败或未完成时保留实际状态，旧总结按历史显示，unknown 保持不可判断。
- 保存配置只取消本安装的旧分析，并忽略晚到结果，活动任务按新配置公平排队。服务离线时继续采集并退避恢复，不解除手动暂停，不下载、更换或启动模型。
- DSH 的暂停只作用于本安装。安装暂停与单聊天暂停取逻辑或，恢复一项不解除另一项，其它安装继续运行。

旧共享模型配置需要重新手填，本轮不迁移、导入或兼容旧格式，也不删除其它观察资料。DSH 安装包目标为 `ghost-agent-sentinel-0.1.3.tgz`，Codex 通过仓库市场安装；正式与 test 安装保持独立身份。

本轮按用户确认不执行升级专项验证。已向用户说明仍有新版真实 App 面板、双端通知领取及 App 退出重开的实机缺口；用户随后要求同步三个分支并递增发布。这些项目继续列为未验，不计通过。自动检查、已取得实机证据及发布状态见 [发布验证范围](release-status.md)。

## 0.1.1 · 2026-10-15

首个正式发布的 DSH 框架版本，包含本机只读采集、共享核心、六项检查及多级代理观察。

- 右侧全局总览按主会话分组；当前会话通过紧凑 GS 入口查看自身及后代。两处界面突出问题、支持隐藏正常，依据紧随对应节点。
- 绿、黄、红、灰四类状态独立计数，区分静默、合理等待、告警与覆盖缺口；已结束代理退出运行计数，仍运行的后代保留。
- 子代理使用委派任务和有效用户限制，材料及引用按代理隔离；公平轮流分析，独立冷却 60 秒，可复用条件未变的有效结果。
- 同主会话告警最多等待 3 秒合并，同问题重复通知至少间隔 10 分钟；面板关闭后后台持续。
- 观察资料滚动保留 24 小时，显式敏感字段省略，资源有界回收，取消后忽略晚到结果。

安装文件为 `ghost-agent-sentinel-0.1.1.tgz`，通过 DSH 第三方插件入口选择解压后的 `package` 目录。本版不发布到 npm，不启动或附带模型服务，不修改宿主 SDK。

运行代码与已验收的 `0.1.0-dev.16` 相同。完整宿主能力要求及验收局限见 [安装说明](installation.md) 和 [发布验证范围](release-status.md)。

`v0.1.0` 的源码 tag 保留，但未创建正式 Release：首次远端门禁发现本机 Homebrew Node 与官方运行时使用不同 zlib，导致压缩包哈希不同。v0.1.1 固定官方 Node.js 24.21.0 与 npm 11.19.1，并让 npm 子进程使用同一 Node，修复发布构建一致性；运行代码保持不变。
