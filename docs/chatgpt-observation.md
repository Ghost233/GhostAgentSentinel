# ChatGPT.app 只读观察开发候选

2026-10-17 生命周期修正：独立常驻辅助后台方案已撤回，`SMAppService` 修复与安装测试停止。插件启用后应在 App 打开时自动观察，关闭面板后持续运行，停用插件或退出 App 后回收观察进程。真实生命周期验证保留为交付前门禁，可先完成其它独立功能。下文的辅助 App、待机清理和注册命令仅保留为旧候选记录，不作为当前安装建议。

当前源码候选为 0.1.2-dev.0，ChatGPT 适配子包为 0.1.0-dev.1。已发布的 DSH 版本仍为 0.1.1。本页说明当前开发状态，不能作为正式 ChatGPT 安装或完整监控通过的证明。

## 当前能力

源码已将主会话生命周期、用户请求、代理输出和工具材料接入共享核心 HTTP。生产辅助进程启用六项检查，鉴权 MCP 面板区分分析结果、排队、未配置和失败。生命周期诊断模式仍只提供灰色观察，不调度分析。

适配器通过每次请求的原生线程身份绑定当前主聊天。它使用公开只读元数据及版本锁定的本机记录，核对 App 所属执行进程、启动代次、版本、插件资格和文件身份。来源在读取期间失效时丢弃晚到状态。

同一安装与 App 执行域共用一个来源。主聊天以独立线程身份区分；项目资格失效只撤销对应任务，全局停用或 App 失效才关闭整份来源。后台按稳定的创建时间分页扫描未归档、已归档目录，不依赖面板打开。每次扫描最多 4 页，每页最多 50 项；目录最多保留 256 个身份，每个采集批次最多处理 20 个对象。

主记录的目录分类和允许读取根采用同一规则：接受配置的记录根；根目录名为 `sessions` 时，也接受同级的 `archived_sessions`。其它相邻目录仍不在范围。v2 材料采集可读取这两个根内的 `.jsonl` 和 `.jsonl.zst`；旧协议与纯元数据观察仍只接纳 `.jsonl`。归档位置不替代主会话身份、本机归属或项目启用核验。

目录扫描到底只表示本轮目录已读完，不代表整机执行覆盖通过。主聊天与分叉分别统计已核实和待核实数量，子代理排除。执行位置不明的环境拒读正文；opaque environmentId 及 ready 状态不能单独证明本机归属。超出预算、来源不支持和未分类对象在面板详情中说明。

当前读取配置支持安装说明中列出的精确 App／CLI 组合，新增 Codex 26.1021.31345（21828）与 0.164.0-alpha.11.1。公开只读元数据和两份现有主记录已核对，分叉与压缩记录使用受控生产链回归；不代替真实 App 升级验收。未知组合继续显示缺口，公开元数据的 notLoaded 不替代实际执行状态。

历史生产者的版本单独核对。精确 0.162.0-alpha.2 与 0.160.1 的 paginated 历史子集可在完整来源和切点守卫下读取，但用户来源未核实的范围保持上下文缺口；不会把旧角色标签或缺失的触发来源补成用户授权。这项兼容不表示当前 App 可以使用其它执行版本。

请求证明使用同聊天、同执行代次的 item_completed/UserMessage，以及 composer 或 edit_user_message 开始证据。同轮可能有多条 role=user 材料，不能全部当作请求。goal 自动续跑没有已核实的原用户关联，用户角色重放只作上下文；无法确认当前用户请求时保持不可判断。

材料与生命周期共享每次最多 256 KiB 的物理读取，每批最多投递 16 条。正式 v2 另有每次 256 KiB 的解码预算，校验和重放也计入；两份预算由整棵谱系共享。正文摘录最多 240 字符单元，不保留 reasoning。截断、脱敏与未知格式进入覆盖说明。结构化命令结果保留真实退出码；原生 MCP 内层正文尚未核实的部分明确记为省略，不猜测命令与外层调用的关系。

ChatGPT 的纯静默和工具久未结束显示灰色“等待原因未确认”及观察时长，不因此发送停滞告警。其它有依据的问题照常进入告警。最近有活动且证据足够时仍可显示正常。

会话面板提供“暂停本聊天分析／恢复本聊天分析”。暂停按安装身份与独立主聊天 ID 保存，继续采集，停止该聊天的新分析与对应通知；其它聊天和 DSH 不受影响。核心或宿主重开、观察资料到期均不自动恢复。控件核对宿主当前会话及修订号，切换后的晚到响应不能覆盖新聊天。取消本轮不表示底层计算已立即结束，物理请求未结算时仍占用分析名额。

采集或分析首次明确失败会生成持久故障回执，当前面板单独显示“监控故障”。回执保留原结算轮次、时间和安全错误分类；不保存错误正文、路径或凭证。持续同原因去重，恢复只更新面板，再次失败产生新记录。排队、慢计算、有效 unknown、主动取消及未调用模型的配置缺失不算已执行分析失败。回执与当前故障状态各最多 1024 条，保留 24 小时，超出范围有缺口提示。

采集结算另有最多 256 条的私有元数据队列，在核心断连时按顺序保存首次失败与恢复，恢复连接后使用原时间补报。目录读取与每条主聊天读取分别结算，不互相恢复；队列容量或保留到期导致的缺口会进入诊断。

原生通知组件使用独立的 `com.ghostsentinel.notifications` 身份。只有明确点击面板的许可按钮才申请通知权限；拒绝许可时仍可查看检查和故障。任务告警沿用 3 秒合并和成功提交后至少 10 分钟的重复间隔；首次明确监控失败形成一次状态提醒，短暂恢复也不会抹去尚未提交的故障记录。每次提交前重新核对 App、插件和项目资格；停用、资格不明、暂停或执行结束时按范围取消尚未投递的请求。系统接受、通知中心快照、用户动作及实际看见分别记录，不能互相代替。

恢复顺序按整个观察范围及 channel 保存，不只按错误原因比较。较早的另一种失败补报时仍留下历史，不覆盖较新的成功。状态预算也包含恢复水位；排序资料被裁剪时，面板说明“恢复状态未确认”，不把保留的历史失败当作当前已确定未恢复。

材料模式要求核心同时提供主聊天、指令上下文、单聊天暂停、故障回执、chatgpt-fork-context/1、chatgpt-fork-storage/1 和 chatgpt-fork-lineage/1 能力；正式 v2 另要求 chatgpt-fork-compression/1。后台激活还须确认按安装清理和待机过期维护能力，配置原生通知时要求对应通知能力。缺少能力时停止材料采集并显示缺口；生命周期诊断仍按原有较小能力范围运行。元数据请求的真实期限、连接及协议错误保留各自固定分类和 metadata 阶段，不保存原始错误正文。

原生 `Extension` 仅接纳已核实的 `web.search` 及 `search`／`openPage` 动作。完成记录固定读取首条结果的 `snippet`，最多 240 字符，不收集查询、URL、标题或其余结果；多条结果或长摘录标为截断。空结果仅表示网页工具未返回结果，不产生验证成功或用户授权。未知扩展、未知动作及无法映射的结果结构保留明确缺口，不预占结果正文身份。

GitHub 安装的元数据子进程只从 stdout 读取 RPC。stderr 直接丢弃，日志累计量不作为协议失效条件。单条 JSON 响应、未完成响应缓冲、请求数量及真实期限仍有上限；非法响应和异常退出仍按原分类处理。

分叉读取器已接入生产适配器。来源由显式 history_base、同安装精确身份候选、原生序号和字节切点共同核实；同一线程整理后的旧代记录也必须证明唯一匹配，不按修改时间或创建来源猜选。历史用户要求只作有来源的上下文，不升级为当前请求或授权；历史输出、工具和状态不改变本轮活动、状态或验证。

当前执行优先的改造把当前采集和继承补齐分开。当前文件通过自己的身份、文件头、前缀和执行来源核验后，先交付当前请求、状态与工具事实。面板显示短请求和最近活动；继承未补齐时明确提示，相关检查保持不可判断。当前文件自身仍须有界追赶，不能跳到文件尾后直接信任正文。

当前与历史分别保存交付进度，响应丢失或重启后仍用原首采时间重放。当前输入保留待补标记；历史补齐后，新的指令绑定关联真实来源回执，不改写原输入。祖先尚未读完不等于当前来源失效，也不表示完整继承已经核实。已有独立依据的问题和继承缺口同时显示。

暂存历史包保留读取时实际取得的前缀见证，确认位置独立保持。释放前在原预算内重新核验对应范围，证明过短或内容已变时不交付。完整暂存包会预留一次共享事件额度，避免持续的小型当前活动阻止历史补齐。临时校验器占用原读取器名额，并参与关闭和重试清理；恢复沿用原有游标字段。

历史链接有时引用一份存储记录，而独立主会话查询和文件头返回其归属会话。适配器分别保留这两种身份，按已验证的原生文件格式核对它们的关系；不能把任意身份不匹配当作别名接受。原会话与分叉共用原生记录的首次采集时间，各自的检查、当前请求和历史引用仍保持隔离。

分叉最多处理 16 个物理代，活动读取器最多 4 个；合计最多 1024 个继承用户候选，每段最多 4096 项结构证明。读取和交付仍共享 256KiB／16条预算。平铺谱系游标另限 256KiB，不含正文；其它游标默认 16KiB。每泵最多 144 次元数据方法，定位和前后资格核验也计入工作预算。适配器传递固定大小的来源回执，核心核对到真正的历史终点，不向每个新执行复制全部引用。缺失、过期、截断、歧义或超额均保留上下文缺口，不能把幸存的较小材料集当作完整历史。

首次采集时间不会因重复、重启、宿主新代次或旧来源回收而刷新。为防止已到期内容重新出现，核心另保存最多 10000 项、按安装归属隔离的原生身份进度；正文和结果仍保留 24 小时。到期后的进度只保留不含正文、旧任务定位或精确活动时间的过期标记，按来源卸载清理。容量不足明确显示缺口。缺少恢复状态的旧游标显示 cursor-invalid，不能通过清空游标把重读当作新采集。

v2 读取 plain 与原生 .jsonl.zst，先完成压缩完整性校验，再读取所需历史范围；不会生成完整明文临时文件。存储身份在压缩、解压或归档移动后保持，文件头与已确认前缀另作防变核对。并存副本不一致、旧进度无法映射或恢复守卫不匹配时显示缺口，不重置保留时间。独立存储代进度最多 10000 项，按安装卸载时与原生身份进度一起清理。

plain 文件每次读取后再次核对原路径、打开文件的身份、大小和时间。追加时仍先核验已知前缀；若校验期间再次追加，短时原生组件从已打开的只读 fd 克隆稳定视图，按原字节预算完成该视图，不再因每次追加丢掉进度。克隆路径在只读打开后立即删除，文件句柄随读取器关闭回收；后续追加由下一视图重新核验。头部或前缀改写、文件替换及已确认的压缩损坏仍拒绝。普通复制不作为稳定快照的替代。

校验未完成时仍显示灰色“当前记录重验中”，保留已核实请求和活动。稳定视图完成后允许交付对应批次；已有新追加时注明“显示已核实快照 · 正在追赶新增记录”，不声称已覆盖文件最新内容。有实际积压时，后台完成当前有界批次并让出执行后继续，仅选择有积压的读取器；完整目录发现、空闲聊天核对、心跳和通知检查仍按普通轮询节奏进行。单泵 256 KiB、事件额度、前后资格核验、分析公平队列及完成后 60 秒冷却保持。

身份、游标和观察范围均未变化的聊天不重新提交相同材料、重建层级或读取完整 Core 快照。只有存储进度推进时可单独提交原生前缀证明并保存游标，不更新检查结果；用户消息、代理输出、工具及真实执行状态变化仍进入原生产链。模型结果和故障在实际面板读取时从 Core 取得，显式暂停／恢复立即返回新状态；采集缓存只保留采集域故障，模型恢复不会被旧缓存覆盖。空闲不代表完全零工作，轻量发现、文件及权限核对继续，结束、失联、过期及已有时间条件仍更新。

若冷读先遇到早于当前 App 启动的执行开始，适配器先有界预扫同一来源。取得该执行的完成或中断记录并重新核验头部、前缀和文件身份后，从原材料游标重放为历史。预扫不发布材料或推进首采进度；真正尚未结束的旧执行保持不可判断。后续新执行按自己的开始记录恢复常规观察。

已确认更晚的当前执行时，预扫只寻找该执行的生命周期及完整性证明，不要求解释旧执行正文，也不逐个旧结束重扫整份记录。证明范围内的旧开始保留不可判断或真实结束，未支持的旧正文不分配材料身份；当前执行和分叉继承范围仍按原材料格式守卫核对。原生 `FileChange` 目前仅接入已核实的 completed 结果，读取有界 stdout／stderr，不采集补丁和路径，不推断测试退出码或文件内容已经验证。已知子代理开始／结束状态只作范围外记录，不接入子代理。

旧 v2 游标恢复时，App 版本不作为存储身份。旧哈希须匹配一个已支持组合、同一存储键及主聊天／读取范围，随后使用同安装保留的头部和前缀证明重验。没有可信证明、源已改写或生产者不支持时继续拒读。重验期间不发布新材料、不修改首采时间；大记录可能仍需等待。

旧执行缺少结束记录时，已核实的新执行仍可独立接入：本机记录中的新开始须与本轮公开接口确认的执行身份相符，再经来源重验和原材料重放。旧执行保留不可判断及历史缺口，不补造结束；新执行的状态由自己的实际记录决定。接口身份晚于记录更新时继续等待核对，新执行已经结束也可恢复为历史。

会话面板分为当前问题与详情，问题下直接显示小字依据。详情中的六项检查、观察诊断和 24 小时内的检查记录直接展开，不因刷新要求重新点击。历史只包含本安装已监控的执行，选择后明确标为历史；返回当前或切换聊天时清空旧范围，安装前结束的执行不主动重跑模型。通知记录在独立设置面板按需读取，每页最多 20 条，不随分析刷新持续轮询。面板隐藏时停止刷新，恢复仅建立一个循环；销毁页面会清理定时器和在途页面请求，后台采集独立继续。

## 开发入口

从仓库 checkout 准备依赖；ChatGPT 子包与 DSH 包分开管理，DSH 包仍使用宿主 SDK，不新增 npm 运行依赖。

```sh
npm ci --ignore-scripts
npm ci --prefix chatgpt --ignore-scripts
npm run build:record-snapshot
npm run test:chatgpt
```

辅助进程从私有安装配置启动。配置由 prepareInstallation 创建，要求明确的适配器数据目录、核心数据目录及插件身份；不会默认接管日常 DSH 配置。

```sh
node chatgpt/helper-main.mjs --config /absolute/path/to/private/installation.json
```

这是本机辅助进程的内部启动入口，需要 Node 24.21.0 或更新版本，固定启用 v2 原生记录协议；没有用户可选的旧协议配置。用户查看入口仍在 ChatGPT 会话侧面板。当前没有注册登录服务或安装正式辅助 App。

日常启停监控只使用 ChatGPT 的插件开关，无需重启 App。辅助后台在插件停用或 App 不运行时保持待机，停止对应采集、分析和通知。重新启用时重新核对来源，面板连接继续使用同一安装的端口与令牌。端口被其它进程占用、运行身份不明时明确报错，不另起一份后台。

正式辅助后台候选为签名的 `GhostSentinel.app`，身份为 `com.ghostsentinel.helper`。包内包含 Node、观察器和用户级 agent，通过 `SMAppService.agent` 管理。配置文件留在私有安装目录，签名包只保存配置路径。采集在 App、版本及插件资格通过后接入共享核心；清理本客户端不会结束 DSH 使用中的核心。原生通知保留独立的 `com.ghostsentinel.notifications` 身份。

辅助后台待机时仍负责存量资料的过期清理。它通过核心公开诊断取得下一次到期时间，按期限安排维护；核心已退出时可重新连接同一资料目录，清完后只关闭自己的客户端。没有存量资料时不为维护创建核心。维护不登记聊天来源、不读取新聊天、不分析或投递通知，也不改动 DSH 的模型和运行状态。

开发包构建入口如下，使用仓库固定的 Node 24.21.0。输出必须位于独立的 `.scratch` 或临时目录；它不会安装、注册或启动服务。默认签名仅供本机开发验证，不表示已经公证。

```sh
node scripts/build-chatgpt-helper.mjs \
  --out /absolute/path/to/.scratch/helper-candidate \
  --config /absolute/path/to/private/installation.json
```

包内的 `--register`、`--unregister` 和 `--status` 用于安装管理，日常插件开关不调用服务注销。真实服务注册、系统审批、升级卸载和 App 退出／重开均须独立验收。退出／重开留到其它聊天空闲时集中执行，不阻塞后台和插件开关源码开发。

安装管理入口默认输出预览清单，核对签名、包内容、配置归属及现有安装，不激活服务。例如：

```sh
node scripts/manage-chatgpt-helper.mjs install \
  --config /absolute/path/to/private/installation.json \
  --destination /absolute/path/to/Applications/GhostSentinel.app \
  --bundle /absolute/path/to/candidate/GhostSentinel.app
```

明确加上 `--apply` 才执行安装。系统审批或必需核心能力尚未确认时保留维护保护，并列出缺口；批准或补齐后用原操作 ID 和 `--resume` 继续同一事务。日常监控不需要这些管理命令。升级保留观察进度；完整卸载通过公开接口清理本安装材料，再核对服务和进程退出，最后移除本安装文件及鉴权配置。失败结果分别列出已完成步骤和残留，不接管未知旧探针。

ChatGPT 内的插件登记与移除仍由宿主公开工具完成，管理器会列出待处理项。仅移除辅助 App 不能宣称整个插件已卸载。当前安装管理仍属开发候选，下面的实际门禁保持。

安装目录使用私有权限，配置和生成的 MCP 连接保存私有令牌。令牌不进入工具结果、诊断、观察事件或通知。缺少可信插件启用状态时拒绝读取；准备配置本身不会启用宿主插件。
