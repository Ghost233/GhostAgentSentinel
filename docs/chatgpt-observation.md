# ChatGPT.app 只读观察开发候选

当前源码候选为 0.1.2-dev.0，ChatGPT 适配子包为 0.1.0-dev.0。已发布的 DSH 版本仍为 0.1.1。本页说明当前开发状态，不能作为正式 ChatGPT 安装或完整监控通过的证明。

## 当前能力

源码已将主会话生命周期、用户请求、代理输出和工具材料接入共享核心 HTTP。生产辅助进程启用六项检查，鉴权 MCP 面板区分分析结果、排队、未配置和失败。生命周期诊断模式仍只提供灰色观察，不调度分析。

适配器通过每次请求的原生线程身份绑定当前主聊天。它使用公开只读元数据及版本锁定的本机记录，核对 App 所属执行进程、启动代次、版本、插件资格和文件身份。来源在读取期间失效时丢弃晚到状态。

同一安装与 App 执行域共用一个来源。主聊天以独立线程身份区分；项目资格失效只撤销对应任务，全局停用或 App 失效才关闭整份来源。后台按稳定的创建时间分页扫描未归档、已归档目录，不依赖面板打开。每次扫描最多 4 页，每页最多 50 项；目录最多保留 256 个身份，每个采集批次最多处理 20 个对象。

目录扫描到底只表示本轮目录已读完，不代表整机执行覆盖通过。分叉暂保留缺口，子代理排除。执行位置不明的环境拒读正文；opaque environmentId 及 ready 状态不能单独证明本机归属。超出预算、来源不支持和未分类对象在面板详情中说明。

当前读取配置仅核验过 ChatGPT 26.1007.71326（20398）与 bundled native 0.162.0-alpha.17.2。未知版本保守显示缺口。公开元数据服务的 notLoaded 状态不能替代实际桌面执行状态。

请求证明使用同聊天、同执行代次的 item_completed/UserMessage，以及 composer 或 edit_user_message 开始证据。同轮可能有多条 role=user 材料，不能全部当作请求。goal 自动续跑没有已核实的原用户关联，用户角色重放只作上下文；无法确认当前用户请求时保持不可判断。

材料与生命周期共享每次最多 256 KiB 的物理读取，每批最多投递 16 条。正文摘录最多 240 字符单元，不保留 reasoning。截断、脱敏与未知格式进入覆盖说明。结构化命令结果保留真实退出码；原生 MCP 内层正文尚未核实的部分明确记为省略，不猜测命令与外层调用的关系。

ChatGPT 的纯静默和工具久未结束显示灰色“等待原因未确认”及观察时长，不因此发送停滞告警。其它有依据的问题照常进入告警。最近有活动且证据足够时仍可显示正常。

会话面板提供“暂停本聊天分析／恢复本聊天分析”。暂停按安装身份与独立主聊天 ID 保存，继续采集，停止该聊天的新分析与对应通知；其它聊天和 DSH 不受影响。核心或宿主重开、观察资料到期均不自动恢复。控件核对宿主当前会话及修订号，切换后的晚到响应不能覆盖新聊天。取消本轮不表示底层计算已立即结束，物理请求未结算时仍占用分析名额。

采集或分析首次明确失败会生成持久故障回执，当前面板单独显示“监控故障”。回执保留原结算轮次、时间和安全错误分类；不保存错误正文、路径或凭证。持续同原因去重，恢复只更新面板，再次失败产生新记录。排队、慢计算、有效 unknown、主动取消及未调用模型的配置缺失不算已执行分析失败。回执与当前故障状态各最多 1024 条，保留 24 小时，超出范围有缺口提示。

采集结算另有最多 256 条的私有元数据队列，在核心断连时按顺序保存首次失败与恢复，恢复连接后使用原时间补报。目录读取与每条主聊天读取分别结算，不互相恢复；队列容量或保留到期导致的缺口会进入诊断。当前尚未接入 GhostSentinel 原生通知，不把可读回执当作系统已提交通知。

恢复顺序按整个观察范围及 channel 保存，不只按错误原因比较。较早的另一种失败补报时仍留下历史，不覆盖较新的成功。状态预算也包含恢复水位；排序资料被裁剪时，面板说明“恢复状态未确认”，不把保留的历史失败当作当前已确定未恢复。

材料模式要求核心同时提供主聊天、指令上下文、单聊天暂停和故障回执能力。缺少能力时停止材料采集并显示缺口；生命周期诊断仍按原有较小能力范围运行。元数据请求的真实期限、连接及协议错误保留各自固定分类和 metadata 阶段，不保存原始错误正文。

分叉的物理序号、字节边界及历史上下文校验已进入基础模块测试。历史用户要求只作有来源的上下文，不升级为当前请求或授权；历史输出、工具和状态不改变本轮活动、状态或验证。完整分叉读取器尚未接入，整理过的旧代存储仍有来源缺口，分叉工单保持未完成。

## 开发入口

从仓库 checkout 准备依赖；ChatGPT 子包与 DSH 包分开管理，DSH 包仍使用宿主 SDK，不新增 npm 运行依赖。

```sh
npm ci --ignore-scripts
npm ci --prefix chatgpt --ignore-scripts
npm run test:chatgpt
```

辅助进程从私有安装配置启动。配置由 prepareInstallation 创建，要求明确的适配器数据目录、核心数据目录及插件身份；不会默认接管日常 DSH 配置。

```sh
node chatgpt/run.mjs --config /absolute/path/to/private/installation.json
```

这是本机辅助进程的内部启动入口。用户查看入口仍在 ChatGPT 会话侧面板。当前没有注册登录服务、安装或签名 App，正式安装器与运行期恢复由后续阶段交付。

安装目录使用私有权限，配置和生成的 MCP 连接保存私有令牌。令牌不进入工具结果、诊断、观察事件或通知。缺少可信插件启用状态时拒绝读取；准备配置本身不会启用宿主插件。

## 验证范围

确定性检查走受控原生 IO、真实文件读取、生产适配器、真实共享核心 HTTP、鉴权 MCP 及页面桥接。只替换外部 IO，来源状态、读取预算、取消、事件归属和核心业务真实执行。

私有 HTTP 认证已通过受控客户端及上述桌面版本的实际会话面板验证。当前聊天和另一条已核实的本机主聊天完成了切换与重开检查，面板身份随聊天切换；当时的生命周期候选以灰色表示尚无分析结论。这是两条主聊天的有限样本，不代表新的材料候选、全部聊天、分叉或其它宿主版本已经完成实机验收。

原生材料形状另经两个主聊天的只读记录核实，包括普通发送、编辑输入、自动续跑反例及结构化退出码。生产适配器、核心和公开 Chat/JEV HTTP 的确定性检查使用受控外部 IO，不把模型返回模拟成真实宿主操作，也不以这些检查代替新候选的实际面板验收。

本轮新插件先在后台显示已安装、已启用，但 App 面板加载失败；用户在 App 内停用再启用本插件后恢复，随后完成真实观察验证。安装流程须分别核对后台登记与实际入口，不能把后台的启用状态当作 App 已就绪，也不能把这一次恢复步骤当成所有加载错误的通用原因。

冷读期间可能先显示 current-turn-not-observed：会话身份已经确认，当前执行仍需在已读记录中核对。来源、记录或版本无法核实时保留缺口。正式后台、原生通知和 App 退出恢复仍保留独立实测门禁；本轮没有安装常驻服务或重启宿主。

会话暂停、故障回执、受控模型 HTTP 失败恢复及实际页面脚本的定点检查已完成；新候选的实际 App 面板、跨 App 重开持久化与原生通知仍须后续实测。后续范围包括完整分叉接入、故障桌面提醒、24 小时已监控历史，以及单实例后台、升级和按来源卸载。正式交付仍须完成全部本机主聊天覆盖及候选实测。模型准确度和显卡推理速度不作为框架验收门槛。
