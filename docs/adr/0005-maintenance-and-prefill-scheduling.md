# 分开安排监控维护与分析预填

2026-10-28，用户报告监控核心在没有新事件、没有在途分析时仍持续高占用。现有维护会逐任务重扫全部事件，查询和心跳也会触发这项工作。优化须覆盖未配置模型的情况，并让模型等待期间的采集、诊断和界面保持响应。

用户已确认本轮必须接入真实的分析预填。此前“先修 CPU、预填另行后置”的建议未获采纳。契约复用 `/v1/chat/completions` 的零预算路径，以及 `/v1/systemone` 的 `prefill_only` 路径。生成输出流和缓存隔离参数不能替代真实预填及完成证明。

在途期间继续保留原始观察记录，每个代理的待处理请求合并为最新完整材料版本。前一请求确认结束后，再处理后续版本。正常完整分析实际完成后，仍保留每代理 60 秒冷却；条件未变时复用有效结果。失败退避、手动暂停及来源与安装隔离保持。

用户进一步确认：持续后台预填只用于总结模型；实际取得本轮分析机会时固定材料版本，后续材料不反复推迟本轮。JEV 的状态预填纳入接口契约和受支持路径联合验收，不默认启用另一份持续后台预填。

Sentinel 先在本仓库提供[接口交接契约](../gmd-prefill-contract.md)，由用户交给 GMD 项目。GhostSplash 的增量预填实现须先适配并合入约定的当前版本，GMD 与 Sentinel 接入后再联合验收。验收包含 Tiel Coder＋DFlash2 的真实前缀复用与最终生成、受支持的 JEV 路径，并保留 D3 lite／mini 不支持的事实。Sentinel 当前无需 `/v1/completions`，不把它列为交付依赖。

缓存与取消协议尚待 GMD 接受，容量、优先级及维护调度细节仍需讨论。本记录保留已确认范围，尚未批准整套预填设计，也不代表预填已经实现。

2026-10-28，用户随后在 GMD 聊天授权两边沟通协作开发。Sentinel 先实施不依赖预填协议的维护优化：按任务和来源维护事件索引；未到事件过期边界时不扫描全量事件；引用保留按完整归属键查询；未变化的时间检查材料复用，时间条件仍实时计算。索引随补采、过期、回滚、卸载和源码级重开更新，关闭 Core 时回收派生索引与材料缓存。轻量租约与通知检查继续运行，模型调用仍由实际完成推进，不将维护 tick 当作模型重入机会。

小型离线回归已锁定重复扫描和复制问题，并覆盖固定本轮材料与完成后冷却。真实运行 Core 尚未升级，因此不能据此宣称其 CPU 已下降。GMD 与引擎尚不能证明的原生摘要、缓存提交及取消释放继续记录为依赖；不启动或更改现有服务，真实联合验收另行安排。

用户随后确认 Q7：已到期的完整分析优先，按原有代理公平顺序执行；没有完整分析待处理时才预填。已经开始的预填自然结束，不为插队强行中断，采集、界面和时效检查独立继续。

Core 已接入可控的 `analyzer.prefill(input, options)` 调度接缝：与完整分析共用一个在途调用资格；队列每任务仅保留一个键，实际出队时复制最新完整材料；预填只更新自己的状态，不发布总结或重置完整分析冷却。失败退避、暂停、配置替换、关闭和来源清理回收对应临时状态。接缝的 Promise 须由适配器持有到原生安全释放或确认未提交，不能仅因 HTTP 断连就结束；取消后仍等待该 Promise 结算。受控测试用手动结算的 Promise 验证此边界，不冒充原生证据。

生产分析器已连接 GMD 客户端，并提供 `prefill` 方法。只有服务明确声明支持相应协议、模式、代次和操作时间策略时，才使用受管操作；未声明支持的服务保留原普通分析接口，不提交零预算请求。这不是预填失败后的冷回退。客户端按服务时间与单调 elapsed 生成 `gmd1` ID，固定请求字节、模型、地址及代次。202、断连或损坏投递先查原操作，确认安全终态后才以相同 ID 重放已保存结果，不换 ID 重执行；取消不发布晚到结果，404 保持未知。

Core 增加未知进度回调，但不因此释放调用资格；同任务完整分析到期时仍入队，避免显示为永远冷却。单独的生命周期信号用于 Core 关闭时结束自身网络和定时器；它不代表 GMD 的原生占用已解除。异常先保留具体客户端代码与脱敏通信原因，不把它们统一归为未识别错误。

生产链已按安装、任务、执行、当前请求、模型角色、服务与指令版本派生缓存盐；没有当前请求依据时不借用旧输入。后台预填 A 完成并释放后，完整分析冻结当时的 A＋B，直接提交正预算生成；由原生引擎查找前缀并处理剩余输入，不额外提交一次 A＋B 零预算预填。总结与 JEV 实际结果均合法后才发布本轮总结；受验证的原生回执进入分析记录，外部响应中的自称回执不作为证明。

上述先在受控 HTTP、真实生产分析器与隔离 Core 中验证，随后通过 GMD 隔离 PublicGateway 互验文本预填→生成→JEV→附依据总结，以及 JEV 状态预填→判断。后者使用实际 GMD 公开提交、登记与响应转换，但原生事件和结果仍为模拟，不能冒充真实引擎证据。GMD 主应用源码随后完成默认关闭的服务装配，真实 Splash 仍不声明支持；GMD 项目报告其 42 项定点回归与静态分析通过，本项目未重复运行该套检查。实际受管引擎上的重放／协调、真实 Tiel＋DFlash2、JEV 与 CPU／响应联合验收另行保留。当前 GMD 也没有跨崩溃确认旧进程组及子孙全部退出的自动恢复证明；这种未知不能被客户端自动清除。Core 关闭只结束自身网络和定时器，不充当原生释放证明。

GMD 的 `identity_only`／`bound` 未提交证明随后经控制面 HTTP 回归冻结，客户端按本次身份、代次、范围和 `not_started` 解析。有效证明允许本次请求以具体故障结束，释放本次调用资格，队列中其它任务可继续；不触发冷回退，也不证明其它同盐请求已结束。原 HTTP 错误和不完整证明继续保持未知。跨仓合成无效输入已核对实际身份级证明；客户端回归另覆盖绑定证明、断连恢复及取消竞态。迟到的查询失败不能擦除已核实的释放。

Q8 撤回，未形成用户同意回退的决定。原问把后台操作登记额度简称为“预填容量”，用户指出不能由预填资源不足推出完整分析可执行。登记额度与 GPU、显存和上下文资源须分别说明；完整生成自身仍包含输入处理，不能绕过真实资源限制。先核对正常正预算消费请求复用前缀、补齐固定版本输入再生成的链路，不默认增加“预填失败后跳过步骤”的产品分支；Q7 和真实预填联合验收范围不变。

发布准备时，用户要求三仓全部发新版本、完善并开启预填入口后由其下载测试。GMD 0.3.1 因而改为按实际 Splash 的 `splash-prefill/1` 能力声明启用可用模式，不再硬编码关闭；旧协议或不支持组合仍不启用。Sentinel 0.1.9 已能消费该公开声明。该发布决定不把模拟计数记为真实缓存命中，也不关闭真实模型、运行 Core CPU 或 App 退出重开的未验项；当前应用与服务仍不操作。
