# ChatGPT 观察生命周期由插件控制

2026-10-17，本轮场景复核已由用户最终确认。用户撤回独立常驻、停用后仍待机的辅助后台方案。插件启用须自动启动观察，关闭面板继续运行，插件停用或 App 退出须回收对应观察进程；DSH 使用中的共享核心独立保留。

真实宿主须验证启动时机、无面板启动、关闭后持续、停用与退出回收，以及多聊天共享。用户最新要求先推进无需退出 App 的开发和测试，优先验证插件启停回收、关闭面板后持续和多聊天共享。App 冷启动与退出／重开留到最后。启动机制待验证后确定，stdio MCP 和会话钩子的配置支持均不能替代这些证据。已有采集、检查、分叉、暂停、面板和通知成果继续保留。

用户允许轻量会话连接进程，共用唯一完整观察实例；允许安装时审查并信任启动定义。短时原生通知组件保留，完成许可、提交或撤销后退出，不承担常驻观察。App 打开或重开时，插件已启用就须自动启动观察，不等待首次聊天或任务；已有运行聊天时启用须直接接入。观察进程可自行清理退出，资格先撤销，实际退出须核验。

观察启动后持续覆盖全范围，没有运行聊天时仍保留发现和存活检查。无有效材料变化时复用结果；故障、结束、过期和已有时间条件仍可更新状态。先前“无运行聊天就退出”的讨论已撤回。

停用插件保留观察历史、读取进度和手动暂停设置，按原留存规则处理。完整卸载才按本安装清理观察资料与配置，DSH 的资料保留。此前允许等待首次本机任务的选择已被本轮复核替代。

本决策描述已确认目标，不代表宿主能力已验证。启动机制尚待最小真实验证；仅支持 stdio MCP、能声明钩子或完成配置登记，均不能证明已达到自动启动与回收目标。

实现时区分进程资格与材料兼容性。App 身份和运行代次已核实、插件明确启用时，执行记录版本不支持只关闭对应读取器、撤销分析与通知，保留灰色入口和一份轻量存活检查实例。停用、App 退出或全局启用资格不明时，观察与连接进程仍须退出。这是按既有“未知版本显示缺口”和“启用期间持续存活检查”要求作出的实现解释，不是用户新增的后台选择。元数据接口自身不可信时，不能据此推定插件已启用；保留灰色入口也不代表当前版本材料采集已通过。
