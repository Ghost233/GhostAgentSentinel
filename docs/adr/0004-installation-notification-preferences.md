# 按安装管理桌面通知，设置与监控分开

2026-10-20，用户确认 Codex 与 DSH 同时重新设计，并在原型审阅后修正页面边界：监控界面只有“当前问题”和“详情”两个 tab。GS 四灯栏置于顶部并吸顶，在两个 tab 滚动时均保持可见，替代此前底部方案。第一屏只呈现当前问题；没有异常时问题区留空，不添加说明文字。未分析、断连或证据不足仍计为灰色，在详情解释，不能把空白当作正常。详情采用原型的“聚焦摘要”方案。Codex 四灯仍只统计当前主聊天、不含子代理；DSH 当前检查统计当前代理及后代，全局统计已接入对象。

Codex 最终采用“一份插件、两个独立面板”：同一个 GhostSentinel 安装提供会话监控面板和安装设置面板，两者独立打开、独立刷新，共用本安装配置。日常只安装一个正式插件；test 是另一个可选插件，也各自包含这两个面板。正式版不依赖 test，也不提示其未安装。监控刷新不能覆盖设置内容，关闭设置面板不影响监控；停用整个插件则停止对应观察，整体卸载和资料清理仍沿用原安装规则。开发者自有临时测试插件仍须及时清理。

用户在 Q15 澄清对“插件”和“面板”的理解，并于 Q17 确认上述方案，撤销此前另装配对设置插件的要求。原先关于设置插件单独启停、配对查找和卸载的需求不再适用；设置面板不建立另一份观察实例或安装身份。

Codex 设置面板优先使用 App 全局插件入口，无需先进入某条聊天；监控保留会话侧面板。这一全局入口只提供设置，不增加全局监控页。[官方入口说明](https://developers.openai.com/plugins/build/extensions) 定义了 global 与 thread 入口，现有 MCP SDK 允许同一服务登记多个独立 UI 资源；当前 App 中实际打开两个入口的行为仍待验证。若不能支持，先报告证据，再确认备用入口，不默认拆回两个插件。旧探针的历史结果不代替当前候选验收。

DSH 设置放入宿主系统设置中的 Sentinel 页面，不放在监控面板。当前原版子模块已提供 `settings.section` 公开扩展，源码与编译接缝存在，无需修改上游；当前运行宿主实际展示尚未验收。Codex 可复用安装级配置接口，新增独立设置资源和入口，避免与当前会话的刷新及身份状态耦合。这一修正替代此前“监控／设置在同一面板内切换”的方案，也替代 ADR 0003 中旧的设置入口描述；模型职责和安装归属不变。

监控刷新、切换聊天或返回监控不能覆盖设置草稿、改变设置页面或打断控件操作。2026-10-20，用户确认加入顶部吸顶 GS 栏后的更新原型，布局设计已确认，以本文所述布局和设置归属为后续规格依据。设计确认不代表功能已实现或验收。

正式 Codex、test 与 DSH 各自保存任务告警和监控故障的桌面通知偏好，两类默认开启。偏好不代替系统许可，关闭通知不停止采集、分析或面板问题显示。关闭某类通知会停止本安装该类尚未提交的提醒，已显示通知保留；重新开启不补发关闭期间积压的历史通知。这修正了当前只有系统授权、没有独立投递偏好的设计，避免借用分析暂停或修改共享系统许可来表达单安装的通知选择。

安装设置面板内分为“设置”“通知记录”“连接诊断”三个 tab，分别呈现模型和通知配置、实际投递记录、连接与采集诊断，不再将后两项折叠在配置表单下。切换 tab 保留正在编辑的内容和已保存状态。监控面板仍只有“当前问题”“详情”两个 tab，不混入设置内容。

通知许可与两类开关放在设置 tab，投递记录放在通知记录 tab；监控中的问题只保留简短投递状态。系统接受、通知中心记录与用户看见继续区分。Codex 原生许可与 DSH 浏览器许可使用各自实际宿主能力，不把某一安装的偏好解释为其它安装已获许可。

通知记录默认汇总本安装所有已监控聊天，每条记录标明聊天名称和投递状态；正式版、test 与 DSH 的记录各自隔离。用户于 Q19 确认同时采用时间与数量上限：只保留最近 24 小时内的最新 1000 条通知记录，两类通知合计计算；超过 1000 条时仅保留最新部分，不足 1000 条也不补入超过 24 小时的旧记录。

设置修改后自动保存。通知开关立即保存；同一模型的“服务地址＋模型”作为一组，在选定模型或离开该分组且内容格式有效时自动保存。输入不完整或格式错误只保留草稿，旧有效配置继续使用；保存不要求服务当时在线，不逐字取消并重排分析。页面显示保存中、已保存或保存失败，失败保留输入和页面位置。既有模型连接检查仍只核对服务在线与模型名称，保存的分析副作用及各安装隔离保持原契约。

总结模型和 JEV 每组分别提供“读取列表”和“检查连接”两个按钮。读取列表只刷新可选模型，不自动选模、保存或宣告连接检查通过；检查连接单独核对服务在线及所填模型名称，不调用推理。操作结果分别显示，连接诊断 tab 保留对应连接检查结果；修改连接内容后，不将旧检查结果当作新内容已通过。

同一安装的多个设置窗口以最后一次完成有效编辑并保存的输入为准，由用户自行协调相互覆盖。不增加冲突选择或配置合并界面。正式版、test 和 DSH 的安装隔离保持；无效输入和保存失败不能显示为已生效。这是用户对 Q14 的最新决定，替代此前建议的人工冲突选择流程，现有代码的冲突拒写行为尚未据此修改。

代码核对仅确认当前混排、重新展开配置会重读及整页重载会丢失查看位置，尚未确定用户这次“刷新走”的具体触发路径。新设计约束不能作为缺陷已经修复的证据。本轮先讨论并制作演示原型，不安装插件、不测试 Inspect、不操作 App，也不改动已发布的 0.1.4。
