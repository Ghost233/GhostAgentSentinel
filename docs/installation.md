# 安装与逐后台接入

本轮 DSH 与 Codex 的安装版本统一为 0.2.4。本文说明 DSH 安装方式，Codex 使用 [GitHub 安装说明](chatgpt-github-installation.md)。Codex 的添加路径为“插件 → 个人 → GhostSentinel（或 GhostSentinel test）→ 添加”。自动检查、原版宿主证据和仍未完成的实机项目见 [发布验证范围](release-status.md)。

每份独立 DSH 配置启用一次 Sentinel；同一配置的多个窗口共用 Host 时无需重复安装。使用同一监控数据目录的后台共用一个核心，各安装分别保存模型配置和分析暂停状态。

## 安装发布包

安装前请阅读本版的验证范围；版本号不表示所有宿主场景均已实机验证。

1. 从 [GitHub 发布页](https://github.com/Ghost233/GhostAgentSentinel/releases) 下载 `ghost-agent-sentinel-0.2.4.tgz` 和 `SHA256SUMS`。
2. 校验下载文件，在长期保留的空目录中解压。
3. 在已有 DSH 实例的“插件 → 安装第三方插件”中选择解压后的 `package` 目录，安装并启用 `ghost-agent-sentinel`。
4. 在右侧“新标签页 → Sentinel”打开全局总览，核对来源清单。聊天输入框下方的 `GS` 打开当前会话检查；只读会话使用顶部备用入口。

macOS 解压示例：

```sh
shasum -a 256 -c SHA256SUMS
mkdir sentinel-0.2.4
tar -xzf ghost-agent-sentinel-0.2.4.tgz -C sentinel-0.2.4
```

选择 `sentinel-0.2.4/package`，不要选择 `.tgz` 文件。目录安装可能使用 link，安装后需要保留目录。本包没有 npm 运行依赖或安装脚本，普通用户无需运行 `npm install`。

升级时保留旧目录，在另一空目录解压新版本，再通过 DSH 安装入口升级。安装器要求重开或已确认模块缓存仍旧时，先核对运行任务和未保存输入，再正常关闭并重开同一配置；仅看到版本号改变不能证明新模块已加载。

本轮按用户确认不执行升级专项验证。上述操作说明不代表旧版本升级、新旧包切换或真实 App 退出重开已经通过。

更新插件文件不会让已运行的旧 Core 自动获得新接口。客户端确认缺少通知记录或撤销能力时，会明确报不支持；未发出的保存请求记为拒绝，采集及其它安装不因这次拒绝而停止。

需要切换共享 Core 时，由用户选择维护窗口。先停用所有使用该 Core 的 Sentinel 来源，等待旧 Core 保存并自然退出；确认退出后，先启用一个新版安装，再恢复其余来源。不要按固定时限强杀 Core。本文只说明人工操作顺序，本轮不执行这些操作，也不将其计为升级通过。

## 宿主兼容性

DSH Host 需要 Node.js 22.13 或更新版本，支持内置 `node:sqlite`，并提供本包使用的 DSH SDK、React、右侧标签页及会话入口。0.2.4 以原版宿主公开能力为准，不修改客户端或 SDK；最终测试输入和结果须按候选另行记录。既有证据的目标为提交 `687f282e8625c6b8d11ff58211a90524be2e4317`、版本 `0.2.1-rc.2`，不代表本轮新界面已经实测。

| 能力 | 要求与缺失时的表现 |
|---|---|
| 多级历史补采 | 原版公开接口缺少冷日志物理／解码预算和可恢复游标时，拒绝不受预算约束的补读；未读分支保留覆盖缺口 |
| 父代理等待依据 | 原版公开接口无法可靠区分 await 与 fire-and-forget 时，不生成等待豁免，也不从子代理活动推断父代理正在等待 |
| 桌面通知 | 连接中的前端客户端及已授予的通知权限；拒绝或未连接时记录实际提交状态 |

v0.1.1 的历史实机验收使用过分页与父等待审计扩展，扩展未随安装包发布。那些结果保留原范围，不代表当前原版宿主具备同样能力。材料不足的检查保持不可判断，缺失能力或跳过项目不计通过。本轮也不恢复旧 SDK 补丁。

## 来源覆盖与后台运行

首次启用具有稳定配置身份的适配器时，核心会把该配置加入尚未手动管理的预期来源清单。手动保存后，以保存的清单为准；清单外来源单独列出。显示名称相同不代表同一来源。

| 状态 | 含义 |
|---|---|
| 等待首次连接 | 已配置，尚未见到该来源 |
| 已连接，等待基线 | 已接入，任务范围仍在核对 |
| 已连接 | 当前有连接并已建立基线 |
| 已断开 | 已见过该来源，当前没有有效连接 |
| 清单项已停用 | 该项不再属于预期连接范围 |

清单全部连接也不保证整机发现完整。其他独立 CLI/Web 配置需要各自安装并启用；本次发布没有验证所有官方 CLI 包装器或发行安装环境。

停用清单项不会停用实际 Host 插件。停止某后台采集，应在对应 DSH 配置中停用 Sentinel。DSH 面板的“暂停分析”只暂停本安装的分析和对应告警，暂停期间仍采集，Codex 正式版与 test 不受影响。Codex 还可单独暂停某聊天；安装暂停或聊天暂停任一生效时，该聊天保持暂停。

在 DSH 宿主系统设置中打开 Sentinel，分别设置总结模型与 JEV 判断模型。每组有效编辑自动保存，各有“读取列表”和“检查连接”；相同安装内各会话共用设置，其它安装独立。旧共享模型配置需要重新填写。保存后只取消本安装的旧分析，并按新配置重新排队，不解除手动暂停。

设置中的“通知记录”和“连接诊断”各占一个 tab。任务告警开关独立于分析暂停；DSH 监控故障通知显示“暂不支持”。安装记录按页读取，两类合计只保留最近 24 小时内最新 1000 条，系统接受不等于用户已看见。监控页按“当前问题／详情”查看，顶部 GS 在滚动时固定。

隐藏、切换或关闭总览后停止面板完整快照刷新，Host 心跳、采集、分析和通知检查继续。通知仍要求客户端连接及授权。最后一个来源退出或失联后，核心保存资料并在宽限期结束后退出，不停止模型服务。

模型配置、保留期限和只读范围见 [README](../README.md)；框架验收与模型质量的边界见 [发布验证范围](release-status.md)。
