# 安装与逐后台接入

v0.1.0 面向本机 DSH。每份独立 DSH 配置启用一次 Sentinel；同一配置的多个窗口共用 Host 时无需重复安装。使用同一监控数据目录的后台共用一个核心。

## 安装发布包

1. 从 [GitHub 发布页](https://github.com/Ghost233/GhostAgentSentinel/releases/tag/v0.1.0) 下载 `ghost-agent-sentinel-0.1.0.tgz` 和 `SHA256SUMS`。
2. 校验下载文件，在长期保留的空目录中解压。
3. 在已有 DSH 实例的“插件 → 安装第三方插件”中选择解压后的 `package` 目录，安装并启用 `ghost-agent-sentinel`。
4. 在右侧“新标签页 → Sentinel”打开全局总览，核对来源清单。聊天输入框下方的 `GS` 打开当前会话检查；只读会话使用顶部备用入口。

macOS 解压示例：

```sh
shasum -a 256 -c SHA256SUMS
mkdir sentinel-0.1.0
tar -xzf ghost-agent-sentinel-0.1.0.tgz -C sentinel-0.1.0
```

选择 `sentinel-0.1.0/package`，不要选择 `.tgz` 文件。目录安装可能使用 link，安装后需要保留目录。本包没有 npm 运行依赖或安装脚本，普通用户无需运行 `npm install`。

升级时保留旧目录，在另一空目录解压新版本，再通过 DSH 安装入口升级。安装器要求重开或已确认模块缓存仍旧时，先核对运行任务和未保存输入，再正常关闭并重开同一配置；仅看到版本号改变不能证明新模块已加载。

## 宿主兼容性

DSH Host 需要 Node.js 22.13 或更新版本，支持内置 `node:sqlite`，并提供本包使用的 DSH SDK、React、右侧标签页及会话扩展入口。源码与安装包已在 Node.js 24 和 26 验证，真实安装验收使用具备下列扩展能力的 DSH SDK。

| 能力 | 要求与缺失时的表现 |
|---|---|
| 多级历史补采 | `sessionQuery.observeSessionPage` 只读分页接口；缺失时保留采集缺口，不把未读分支当作完整覆盖 |
| 父代理等待依据 | `subagents.parentWaitAuditVersion === 1` 及 `observeWaitCaller` 实时审计；缺失时不能仅凭没有输出推定合理等待 |
| 桌面通知 | 连接中的前端客户端及已授予的通知权限；拒绝或未连接时记录实际提交状态 |

上述 SDK 分页和等待审计扩展不包含在 Sentinel 安装包中。本次真实验收使用过相应宿主源码扩展，不代表所有官方 DSH 安装版本都提供这些接口。旧宿主会明确显示覆盖缺口或不可判断；需要完整能力时，应先由宿主提供兼容接口。本仓库不会在安装时修改 DSH SDK。

## 来源覆盖与后台运行

首次启用具有稳定配置身份的适配器时，核心会把该配置加入尚未手动管理的预期来源清单。手动保存后，以保存的清单为准；清单外来源单独列出。显示名称相同不代表同一来源。

| 状态 | 含义 |
|---|---|
| 等待首次连接 | 已配置，尚未见到该来源 |
| 已连接，等待基线 | 已接入，任务范围仍在核对 |
| 已连接 | 当前有连接并已建立基线 |
| 已断开 | 已见过该来源，当前没有有效连接 |
| 清单项已停用 | 该项不再属于预期连接范围 |

清单全部连接也不保证整机发现完整。其他独立 CLI/Web 配置需要各自安装并启用；本次发布没有验证所有官方 CLI 包装器或发行安装环境。

停用清单项不会停用实际 Host 插件。停止某后台采集，应在对应 DSH 配置中停用 Sentinel。共享核心的“暂停分析”对全部接入来源生效，暂停期间仍采集。

隐藏、切换或关闭总览后停止面板完整快照刷新，Host 心跳、采集、分析和通知检查继续。通知仍要求客户端连接及授权。最后一个来源退出或失联后，核心保存资料并在宽限期结束后退出，不停止模型服务。

模型配置、保留期限和只读范围见 [README](../README.md)；框架验收与模型质量的边界见 [发布验证范围](release-status.md)。
