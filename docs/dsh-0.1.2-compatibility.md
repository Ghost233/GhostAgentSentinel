# DSH 0.1.2 兼容验证与发布准备

## 版本与发布条件

DSH 已发布版本保持 `0.1.1`。开发源码版本为 `0.1.2-dev.0`，通过本页门槛后再准备正式 `0.1.2`。本轮准备不替换日常使用中的 DSH 插件。

Codex GitHub 插件保持 `0.1.2-preview.2`。App 退出／重开等实机验收仍未完成。两个适配器共用部分源码，但分别记录版本、验收范围和发布状态。

收尾顺序为：先提交可安装的 Codex 预览版，再完成 DSH 兼容验证，通过后才提交和发布 DSH 0.1.2。Codex 预览版已推送，市场固定至 `ec3c7b345c29267689aa7b273325f63124efb424`；本页仅安排 DSH 后续验证，不提前调整 DSH 版本或安装包清单。

比较 `v0.1.1` 与 `2cd96147ed0dde92bb2eac2ce4b18ae00791e590`，`dsh/` 没有变化。共享核心、分析、协议、层级和状态投影已有变化。Codex 已通过的检查不能代替 DSH 回归。

## 原版宿主边界

目标使用 `DSH-Workflow/deepseek-harness` 子模块对应的原版 DSH。2026-10-19 只读核对时，提交为 `687f282e8625c6b8d11ff58211a90524be2e4317`，源码版本为 `0.2.1-rc.2`，工作区干净。

实机开始前，还须核对客户端、SDK 构建产物和目标提交。子模块源码干净、测试加载成功，都不能单独证明桌面客户端正在使用该提交。目标变化后，重新记录输入并复核受影响的证据。

本轮不修改上游源码，不恢复旧 SDK 扩展。公开接口不支持的能力显示缺口，相关正向场景记为不支持，不算通过。拒读、缺口表达、取消、只读和回收要求继续执行。

## 集中验收清单

| 门槛 | 要验证的行为 | 完成证据 |
| --- | --- | --- |
| 原版 DSH 现有功能 | 原生代理与工具采集、多级归属、六项结果及不可判断、暂停恢复、全局总览与 GS、隐藏或关闭面板后持续。缺少冷读或等待证明时明确显示缺口。 | 原版客户端身份、最终包、真实原生事件、公开快照及实际界面。 |
| 共享核心兼容 | DSH 与 Codex 同时接入。分别检查 DSH 先启动和 Codex 先启动；旧 DSH 0.1.1 与新核心的兼容性也须核对。已有核心能力不足时说明缺口，不能为接入另一方强制关闭核心。 | 核心实例身份、能力回执、两方持续心跳与真实增量、调度和连接记录。 |
| 来源与资料隔离 | 同名聊天、相同局部任务 ID、不同来源和执行代次不串请求、材料、分析、暂停设置或历史。 | 按来源和执行核对的公开结果、引用及资料保留记录。 |
| 通知归属 | DSH 领取和确认自己的通知，Codex 原生组件只处理本安装通知。故障合并、取消和晚到回执不影响另一方。系统提交与用户看见分别记录。 | 两类通知的来源、任务、尝试身份和回执；受影响的实际投递路径。 |
| 单方停用与卸载 | 分别停用、卸载 DSH 和 Codex；另一方继续采集、分析并使用原核心，自己的资料保持。停用保留资料，完整卸载按所属范围清理。 | 双向操作前后实例身份、持续增量、请求回收及范围清理核对。 |
| 单方升级 | 分别升级 DSH 和 Codex，另一方不中断。保留来源身份、已采集资料和用户设置；不强制替换正在被使用的核心。 | 升级事务、包身份、另一方连续性及恢复后的公开结果。 |
| 最终发布 | 固定输入后完成本地门禁、适用范围复审、包检查、正式发布及引用同步。 | [发布流程与完成条件](release-status.md#发布流程与完成条件)要求的记录。 |

DSH 的实机检查优先使用后台只读接口。必要界面操作集中完成，不反复打开、前置或重启日常实例。合成测试只操作自有对象，临时插件显示名以 `test` 结尾，用后清理。Codex 的 App 退出／重开继续留到最后安排，不以本轮 DSH 结果代验。

## 证据复用与当前进度

旧 DSH 0.1.1 的界面和扩展 SDK 证据保留原范围。适配器未变可以减少重复操作；共享核心的行为变化、原版接口差异和桌面构建身份仍须补验。

Codex 的 GitHub 登记、正常版与测试版安装、运行包完整性及按渠道卸载结果可复用。它们不证明 DSH 与 Codex 已在真实宿主同时运行，也不替代 DSH 通知归属和生命周期检查。

2026-10-19，本地定向回归加载了子模块构建环境：219 项通过，0 项失败，13 项因缺少有界冷读或父等待审计接口而跳过。实际 DSH 包组合和客户端模块加载检查通过。此结果用于本地 SDK 集成和共享核心 HTTP 行为，未宣称原版桌面客户端实机通过。

本轮记录保存在 `.scratch/dsh-0.1.2-compatibility/`。原版客户端实机、双端同时运行、双向停用／升级／卸载及最终发布门禁仍待完成。现阶段不创建 `v0.1.2` tag，不发布 DSH 0.1.2。

提交正式版本前，仍须针对最终输入执行 `npm run check`、`npm test`、`npm run test:resources` 和发布包检查。本页定向回归不替代这些完整门禁。模型判断准确度、显卡拥堵和推理速度不作为本轮框架验收条件。
