# GhostAgentSentinel

面向 AI agent 的本机只读执行监控工具。共享核心连接 DSH 与 Codex：DSH 观察主代理及多级子代理，Codex 观察本机主聊天及分叉主会话。当前源码及两端安装版本统一为 0.1.4，按用户要求从 0.1.3 累加一个补丁版本。

Codex 适配器只保留会话侧面板。本版包含主聊天发现、原生请求证明、六项检查、单聊天暂停、故障回执及 24 小时已监控历史，也加入安装级模型设置与附依据的执行短总结。紧凑面板把依据放在每条问题下，通知记录区分提交、送达快照和用户动作。完整自动检查与已取得的原版 DSH 证据见 [发布验证范围](docs/release-status.md)。新版真实 App 面板、部分双端通知与 App 退出重开仍有未验项，不能将本次发布当作这些项目已通过。

## 安装

DSH 0.1.4 安装包为 `ghost-agent-sentinel-0.1.4.tgz`，从 [GitHub 发布页](https://github.com/Ghost233/GhostAgentSentinel/releases) 下载并解压到长期保留的目录。在 DSH 的“插件 → 安装第三方插件”中选择解压后的 `package` 目录，安装并启用 `ghost-agent-sentinel`。此前正式基线为 [v0.1.1](https://github.com/Ghost233/GhostAgentSentinel/releases/tag/v0.1.1)。

Codex 通过 [GitHub 仓库市场安装](docs/chatgpt-github-installation.md)。正式安装与名称以小写 `test` 结尾的测试安装可并存，模型配置和暂停状态各自保存。

DSH Host 需要支持 Node.js 22.13 或更新版本及 `node:sqlite`。DSH 插件使用宿主提供的 SDK 和 React，没有 npm 运行依赖或安装脚本。当前原版宿主缺少部分历史补采和父代理等待依据时，明确显示覆盖缺口，见 [安装说明与兼容性](docs/installation.md)。

## 查看运行情况

DSH 使用下列入口。Codex 在当前聊天的 GhostSentinel 会话面板中查看。

- **全局总览**：在右侧“新标签页 → Sentinel”打开，按主会话分组查看已接入后台及其代理树，问题优先，可隐藏正常节点。
- **当前会话检查**：输入框下方的 `GS` 入口显示绿、黄、红、灰四类代理数量。点击后查看当前代理及其后代，依据直接放在对应节点下方。无法显示底部入口的只读会话使用顶部备用入口。
- **后台持续**：隐藏或关闭总览后，后台采集、分析和通知检查继续。桌面通知需要连接中的 DSH 客户端及通知权限。

绿灯表示当前正常或有依据地等待用户／子代理；黄灯表示观察中的疑点或静默；红灯表示已有依据的告警；灰灯表示尚无判断或覆盖缺口。每个活动代理只计一次，已结束节点退出运行计数。新材料排队时，可保留仍有效的上轮绿灯并标注“上轮正常 · 待分析”。

首次检查没有可见执行活动可显示黄灯；已有活动后，连续静默至少 60 秒再黄。代理文字、工具开始和工具结果均算活动。黄灯本身不发送桌面告警，无输出也不等于卡死。

## 接入与模型配置

每份独立 DSH 配置启用一次插件。使用同一监控数据目录的后台共用核心；总览的来源清单显示已连接、等待连接、断开及停用的配置。清单只覆盖已登记范围，不保证自动发现整机全部后台。

每份安装独立保存总结模型和 JEV 判断模型，同一安装内的聊天共用设置。DSH、Codex 正式版与 test 可选择同一服务，修改一方的设置只影响该安装。旧共享模型配置需要重新手填，不迁移或导入，也不删除其它观察资料。

在 Codex 会话面板顶部打开固定的“设置”；采集失败或当前会话尚未确认时，设置仍可使用。在 DSH 面板中展开“本地分析连接”。分别填写两个角色的服务地址和模型 ID，再保存本安装的配置。

总结模型使用 `/v1/chat/completions`，JEV 判断使用 `/v1/systemone`。两个地址可相同，只接受回环 HTTP(S) 地址，不保存 API 密钥。普通聊天接口可用不证明 JEV 判断接口可用。插件不下载、更换或启动模型。

Codex 的“读取列表／检查连接”只读取 `GET /v1/models`，提供目录选择并保留手填。检查不发送聊天材料或推理请求。服务在线、模型可见与本轮分析成功分别显示；模型可见不证明 JEV 能力已经验证。

本轮总结模型和 JEV 均成功，且输出与引用有效后，才发布附依据的 1～2 句执行短总结。任一环节失败或未完成时，不发布新总结，旧总结按历史显示。保存配置会取消本安装的旧分析并忽略晚到结果，活动任务按新配置公平排队。采集、原任务及其它安装继续运行，手动暂停保持。

未配置模型或模型失败时仍采集，并如实显示依赖失败、不可判断、排队和滞后。失败后沿用分析队列退避，默认间隔为 60、120、240、480 秒，最长 900 秒。同一服务和模型恢复后自动继续合法分析；恢复不解除手动暂停。模型判断准确度、GPU 拥堵和推理耗时不属于本次框架发布的验收承诺。

## 数据和提醒

默认保存到 `~/.ghost-agent-sentinel`。任务身份、状态、输入、输出和工具记录以短摘录保留，默认每条最多 240 字符单元，截断与缺口会标明。观察事件、摘要、证据和告警滚动保存 24 小时；来源配置另行持久保存。插件不会给原聊天发消息、控制原任务或主动读取工作区补采版本指纹。

显式认证头、常见凭据字段、私钥和已识别的凭据读取命令在采集与核心接收处整字段省略，并标明缺口。该规则不能识别任意形式的秘密文本。

六项检查包括推进不足、偏离请求、同类返工、完整验证重复成本、当前版本本地验证缺口和长等待。子代理按实际委派任务及仍有效的用户限制检查；缺少应有证据时保留不可判断。活动代理公平排队，各自在一轮分析结束后冷却 60 秒；成功且条件未变的结果可复用。

同一主会话的多代理告警最多等待 3 秒合并为通知，同一持续问题至少间隔 10 分钟再次提醒。任务结束、来源失联或依据失效时停止对应重复提醒。系统接受通知与用户实际看见分别表达。取消分析会忽略晚到结果，底层模型计算可能稍后结束。

## 开发与验证

源码测试在本地 macOS arm64 完成，依赖已构建的 DSH-Workflow SDK 与其测试解析器。默认查找同级 `DSH-Workflow` 目录，也可指定绝对路径：

```sh
npm ci --ignore-scripts
npm ci --prefix chatgpt --ignore-scripts
export DSH_WORKFLOW_ROOT=/absolute/path/to/DSH-Workflow
npm run check
npm test
npm run test:resources
```

GitHub Actions 只负责打包、核对版本／文件清单／哈希并上传产物，不运行测试或真实宿主验收。仅调整 workflow 时，复用未受影响的本地证据，只验证相关配置和打包；发布门槛见 [发布流程](docs/release-status.md#发布流程与完成条件)。

SDK 缺失时检查会明确失败。普通用户安装发布包不需要这套开发环境。运行包不包含合成测试驱动、真实会话记录、模型服务或本机连接信息。
