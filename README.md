# GhostAgentSentinel

面向 AI agent 的本机只读执行监控工具。已发布的 v0.1.1 提供共享核心与 DSH 适配器，观察已接入后台中的主代理及多级子代理。当前源码为 0.1.2-dev.0 开发候选，开始接入 ChatGPT.app 本机主会话；正式安装与完整框架验收尚未完成。

ChatGPT 适配器只保留会话侧面板，不包含子代理或全局总览。当前阶段提供真实生命周期与来源核对，六项语义分析明确显示尚未接入。开发入口与实测边界见 [ChatGPT 只读观察](docs/chatgpt-observation.md)。

## 安装

从 [v0.1.1 发布页](https://github.com/Ghost233/GhostAgentSentinel/releases/tag/v0.1.1) 下载 `ghost-agent-sentinel-0.1.1.tgz`，解压到长期保留的目录。在 DSH 的“插件 → 安装第三方插件”中选择解压后的 `package` 目录，安装并启用 `ghost-agent-sentinel`。

运行需要支持 Node.js 22.13 或更新版本及 `node:sqlite` 的 DSH Host。插件使用宿主提供的 DSH SDK 和 React，没有 npm 运行依赖或安装脚本。完整多级历史补采和父代理等待识别依赖宿主能力，见 [安装说明与兼容性](docs/installation.md)。

## 查看运行情况

- **全局总览**：在右侧“新标签页 → Sentinel”打开，按主会话分组查看已接入后台及其代理树，问题优先，可隐藏正常节点。
- **当前会话检查**：输入框下方的 `GS` 入口显示绿、黄、红、灰四类代理数量。点击后查看当前代理及其后代，依据直接放在对应节点下方。无法显示底部入口的只读会话使用顶部备用入口。
- **后台持续**：隐藏或关闭总览后，后台采集、分析和通知检查继续。桌面通知需要连接中的 DSH 客户端及通知权限。

绿灯表示当前正常或有依据地等待用户／子代理；黄灯表示观察中的疑点或静默；红灯表示已有依据的告警；灰灯表示尚无判断或覆盖缺口。每个活动代理只计一次，已结束节点退出运行计数。新材料排队时，可保留仍有效的上轮绿灯并标注“上轮正常 · 待分析”。

首次检查没有可见执行活动可显示黄灯；已有活动后，连续静默至少 60 秒再黄。代理文字、工具开始和工具结果均算活动。黄灯本身不发送桌面告警，无输出也不等于卡死。

## 接入与模型配置

每份独立 DSH 配置启用一次插件。使用同一监控数据目录的后台共用核心；总览的来源清单显示已连接、等待连接、断开及停用的配置。清单只覆盖已登记范围，不保证自动发现整机全部后台。

摘取模型使用公开 `/v1/chat/completions`，JEV 判断使用 `/v1/systemone`。普通聊天接口可用并不代表 JEV 概率接口可用。两个地址可相同，只接受回环 HTTP(S) 地址；本版不保存 API 密钥，不自动加载或启动模型。

可在面板中配置，或在解压后的 `package` 目录执行：

```sh
node src/daemon.mjs configure \
  --llm-url http://127.0.0.1:54841 --llm-model YOUR_EXTRACTION_MODEL_ID \
  --jev-url http://127.0.0.1:54841 --jev-model YOUR_JEV_MODEL_ID
node src/daemon.mjs status
```

未配置模型或模型失败时仍采集，并如实显示依赖失败、不可判断、排队和滞后。模型判断准确度、GPU 拥堵和推理耗时不属于本次框架发布的验收承诺。

## 数据和提醒

默认保存到 `~/.ghost-agent-sentinel`。任务身份、状态、输入、输出和工具记录以短摘录保留，默认每条最多 240 字符单元，截断与缺口会标明。观察事件、摘要、证据和告警滚动保存 24 小时；来源配置另行持久保存。插件不会给原聊天发消息、控制原任务或主动读取工作区补采版本指纹。

显式认证头、常见凭据字段、私钥和已识别的凭据读取命令在采集与核心接收处整字段省略，并标明缺口。该规则不能识别任意形式的秘密文本。

六项检查包括推进不足、偏离请求、同类返工、完整验证重复成本、当前版本本地验证缺口和长等待。子代理按实际委派任务及仍有效的用户限制检查；缺少应有证据时保留不可判断。活动代理公平排队，各自在一轮分析结束后冷却 60 秒；成功且条件未变的结果可复用。

同一主会话的多代理告警最多等待 3 秒合并为通知，同一持续问题至少间隔 10 分钟再次提醒。任务结束、来源失联或依据失效时停止对应重复提醒。系统接受通知与用户实际看见分别表达。取消分析会忽略晚到结果，底层模型计算可能稍后结束。

## 开发与验证

源码测试依赖已构建的 DSH-Workflow SDK 与其测试解析器。默认查找同级 `DSH-Workflow` 目录，也可指定绝对路径：

```sh
npm ci --ignore-scripts
npm ci --prefix chatgpt --ignore-scripts
export DSH_WORKFLOW_ROOT=/absolute/path/to/DSH-Workflow
npm run check
npm test
npm run test:resources
```

SDK 缺失时检查会明确失败。普通用户安装发布包不需要这套开发环境。运行包不包含合成测试驱动、真实会话记录、模型服务或本机连接信息。
